# JobPilot 面试讲解与学习指南

这份文档用于帮助项目作者真正理解 JobPilot，而不是只会运行程序。

## 1. 30 秒项目介绍

> JobPilot 是一个基于 Python 实现的本地求职辅助工具。用户输入个人技能和岗位 JD 后，系统会识别中英文技术关键词，计算技能匹配度，输出已匹配技能、缺失技能和学习建议，并生成 Markdown 简历与求职信。当前版本是透明的规则型原型，不依赖 API Key，个人信息只保存在本机。

## 2. 2 分钟项目介绍

> 我做这个项目是因为求职时需要反复阅读岗位 JD、判断自己是否匹配，并针对不同岗位修改简历。JobPilot 把这个流程拆成候选人画像、岗位解析、技能匹配、差距分析和材料生成五个模块。
>
> 在岗位解析部分，我维护了一套中英文技术关键词和别名规则，并使用边界匹配避免子串误识别，例如不会把 `interested` 中的 `rest` 当成 REST 技能。匹配模块会对候选人技能和岗位技能进行标准化，然后计算交集和覆盖率，输出匹配分、已匹配技能和缺失技能。
>
> 工程上，项目提供本地 Web 页面、CLI、JSON 档案管理和 Markdown 文档生成；不安装 Jinja2 时也可以使用内置生成器。项目还包含环境诊断、表单验证、端到端流程和回归测试，并通过 GitHub Actions 自动测试。
>
> 当前项目的边界是规则型关键词匹配，分数不代表真实录用概率。后续可以接入 Embedding 做语义匹配，再使用 LLM 对岗位要求和候选人经历进行结构化分析。

## 3. 项目流程

```text
用户填写个人信息和技能
        ↓
粘贴岗位 JD
        ↓
job.py 识别岗位技能
        ↓
evaluator.py 标准化并计算技能交集
        ↓
输出匹配分、matched skills、missing skills
        ↓
generator.py 生成简历和求职信
        ↓
webapp.py 在网页中展示并提供下载
```

## 4. 重点文件

| 文件 | 作用 | 面试时怎么说 |
|---|---|---|
| `run.py` | 寻找可用端口并启动网页 | 项目的一键启动入口 |
| `webapp.py` | 接收表单、调用业务模块、展示和下载结果 | Web 层和业务层分开 |
| `ai_job_assistant/profile.py` | 定义候选人信息并读写 JSON | 使用结构化数据管理用户档案 |
| `ai_job_assistant/job.py` | 解析岗位文本并识别技能 | 把非结构化 JD 转为技能集合 |
| `ai_job_assistant/evaluator.py` | 计算技能覆盖率 | 使用集合交集得到 matched / missing skills |
| `ai_job_assistant/generator.py` | 生成简历和求职信 | 支持模板与无模板回退 |
| `cli.py` | 命令行操作 | 便于自动化和调试 |
| `doctor.py` | 检查 Python 和项目环境 | 改善首次运行体验 |
| `tests/` | 回归与端到端测试 | 防止修改后破坏已有功能 |

## 5. 匹配分怎么计算

核心逻辑可以概括为：

```text
匹配分 = 候选人与岗位共同技能数量 ÷ 岗位识别技能数量 × 100
```

程序会先统一大小写、下划线、连字符和多余空格，然后计算两个技能集合的交集。

示例：

```text
候选人技能：Python、Git、JSON
岗位技能：Python、Git、Docker、SQL

matched_skills = Python、Git
missing_skills = Docker、SQL
score = 2 / 4 × 100 = 50
```

必须主动说明：这是关键词覆盖率，不是录用概率，也不是完整的语义匹配。

## 6. 可以讲的真实 Bug

### Bug 1：英文子串误匹配

问题：简单使用 `in` 可能把 `interested` 中的 `rest` 识别成 REST 技能。

解决：对英文关键词使用单词边界匹配，并添加回归测试。

### Bug 2：GitHub Actions 模块导入失败

问题：仓库同时包含 EvalPilot 和 JobPilot，CI 从根目录运行时无法找到两个 Python 模块根目录。

解决：在工作流中设置根目录和 `jobpilot` 的 `PYTHONPATH`，并使用 `python -m pytest` 运行测试。

### Bug 3：网页版模板渲染异常

问题：HTML/CSS 花括号与 Python 字符串格式化冲突。

解决：转义 CSS 花括号，并增加页面渲染和 HTTP 健康检查测试。

## 7. 高频面试追问

### 为什么不用真正的大模型？

> 第一版先用规则实现，是为了保证成本低、结果透明、可以离线运行，也方便测试。规则版本验证完整流程后，再接入 LLM 或 Embedding，能够更清楚地比较升级前后的效果。

### 规则匹配的缺点是什么？

> 无法理解同义表达、上下文和技能熟练程度；关键词库之外的技能也可能漏掉。它适合做基础筛选，不适合替代招聘决策。

### 怎样升级为真正的 AI 应用？

> 可以先使用 Embedding 计算岗位要求与经历描述的语义相似度，再用 LLM 将 JD 解析为技能、职责、年限、学历等结构化字段，最后结合规则和语义结果形成可解释评分。

### 为什么用 JSON？

> JSON 结构清晰、跨语言、便于人工查看，也适合作为 CLI、Web 页面和后续 API 之间的数据交换格式。

### 为什么写测试？

> 关键词识别和文件生成容易出现回归问题。测试可以保证边界匹配、空输入、错误 JSON、文件覆盖保护和完整 Web 流程在修改后仍然正常。

## 9. 三天学习顺序

### 第一天：会运行、会解释

- 跑通网页；
- 看懂 `run.py`、`webapp.py`；
- 能用 30 秒介绍项目。

### 第二天：理解核心逻辑

- 看懂 `job.py` 和 `evaluator.py`；
- 手算一个匹配分；
- 理解关键词边界和标准化。

### 第三天：理解工程质量

- 看懂 `generator.py`、`doctor.py` 和测试；
- 运行测试；
- 准备 2 分钟项目介绍和 Bug 故事。

## 10. 项目边界

面试中不要声称：

- 已接入 GPT、Claude 或其他真实 LLM；
- 使用了向量数据库或 Embedding；
- 匹配分可以预测录用结果；
- 已部署为商业线上服务。

可以真实地说：

> 这是一个可运行、可测试、可解释的 AI 应用原型，我重点完成了流程拆解、规则设计、Web/CLI 实现和工程化测试，并规划了语义匹配与 LLM 升级路线。
