# 面试准备：LLM 评测 / Prompt / Rubric

## 1. 这个项目是做什么的？

这个项目是一个面向 LLM 评测和编程题质检的个人展示项目，核心是把“模型回答好不好”拆成可复核的评分维度、错误类型、Gold Answer 和 Pass/Fail 示例。

## 2. 什么是 Rubric？

Rubric 可以理解为评分规则。它不是简单给一个分数，而是把评分拆成多个维度，比如正确性、完整性、可解释性、格式规范和边界条件，这样评分更稳定，也更方便复核。

## 3. 为什么需要 Gold Answer？

Gold Answer 是参考答案或标准答案要点。它可以帮助评测员判断模型回答是否覆盖关键逻辑、边界条件和输出要求，减少只凭感觉评分的问题。

## 4. LLM 评测时最重要的是什么？

最重要的是一致性、可复核性和可执行性。也就是不同评测员按照同一套规则评分，结果应该尽量接近，并且每个扣分点都能找到明确证据。

## 5. 如何判断模型回答是否合格？

我会先看它是否解决核心问题，再检查是否覆盖题目约束和边界条件，最后看解释是否清楚、输出格式是否符合要求。如果核心逻辑错了，即使表达完整也不能给高分。

## 6. Prompt 工程在这里起什么作用？

Prompt 的作用是约束模型按照固定维度输出，例如要求它给出 score、error_type、evidence 和 suggestion。这样可以让模型结果更结构化，方便人工复核。

## 7. 为什么 AI 评测不能完全自动化？

因为模型可能出现幻觉、误判和不稳定输出。自动评分可以提高效率，但关键任务仍然需要人工复核，尤其是编程题、推理题和高风险场景。

## 8. 你怎么处理边界条件？

我会在 Gold Answer 和 Rubric 里明确列出边界情况，比如质数判断中 `n <= 1`、`n == 2`、偶数、大数和平方根边界。质检时专门检查模型是否覆盖这些点。

## 9. Pass/Fail 示例有什么用？

Pass/Fail 示例可以让评分规则更直观。只写抽象规则可能理解不一致，但加入正反样例后，评测员更容易判断什么情况应该通过，什么情况应该扣分。

## 10. 这个项目和你的简历方向有什么关系？

我的简历方向是 Prompt 工程、LLM 评测数据构建和编程题质检。这个项目正好展示了我对 Rubric、Gold Answer、错误分类和结构化评分的理解。

## 11. 你目前项目还有什么不足？

目前脚本只是规则化演示，不能替代真实 LLM 评测。后续可以接入 LLM API，让模型根据 Prompt 自动输出评分，再加入人工复核流程。
